# VBAと現行テスト仕様書のカバレッジ確認

確認日: 2026-10-20

対象はルートフォルダの `TS_SVNログからリスト作成.xlsm` と、更新済みの `TS_SVNログからリスト作成_単体テスト.xlsx`（42ケース）。`01.テスト仕様書` 配下の旧版や、更新前のMarkdownを現行仕様として扱っていない。

これはVBAの分岐とテスト記載を比較した静的レビュー。以下は「現行仕様書に明示されていない、または既存ケースだけでは保証できない確認項目」であり、未実施や不具合を断定するものではない。マクロは実行していない。Excelの仕様書・証跡ファイルは変更していない。

通常のリスト作成、PR/AP/BATCHの代表的な除外、案件の完全一致・重複・派生一致・単独の近似一致は既存ケースで扱われている。追加の優先度が高いのは棚卸し反映、SVN情報取得、案件照合の競合条件。全42ケースをやり直す必要はない。

## 次に追加するとよい境界・異常系

| 番号 | 追加候補 | 条件と確認ポイント |
| --- | --- | --- |
| B01 | 近似候補が同程度に複数 | 完全一致・派生一致を置かず、似た案件名を2件以上置く。採用の得点差を満たさない場合は、勝手に1件を選んで配信先を設定しないこと。AOの候補とHの表示も記録する。単独候補のTC-4-1-8/13とは異なる。 |
| B02 | 要件番号・フェーズ番号の相違 | 名前は似ていても要件番号が違う、または両方にあるフェーズ/PH番号が違う案件を用意する。近似一致によって別番号案件を採用しないこと。完全一致や派生一致に当たらない名前で確認する。 |
| B03 | 案件名の表記正規化 | 全角英数字、括弧、会社名の目印など、実運用で使う表記を選ぶ。台帳とログの見た目の差が正規化されることを確認する。TC-4-1-15はチケット/PB接頭辞を扱うが、他の正規化すべてを保証しない。 |
| B04 | 日本語SVNログ・区切り文字・コピー情報 | 日本語見出しのログを入力する。区切り文字空欄による既定値、指定語がファイル行にない場合の代替処理、コピー元情報の付いた行、複数行メッセージをそれぞれ確認する。パス・ファイル名・案件名が崩れず抽出されること。日本語版Excelで動くことと、日本語ログ形式を確認することは別。 |
| B05 | 必須見出し不足 | 他の条件を正常にしてRevision/Author/Date/Message相当の見出しを1つずつ欠落させる。対応するSVN_REV/SVN_ATH/SVN_DATE/SVN_MSGの通知で止まり、成功通知が出ないこと。TC-2-1-3は空入力によるMSG_TYPEエラーだけ。 |
| B06 | 台帳ファイルはあるがデータを読めない | ヘッダーのみの空台帳、案件名または本実施環境の見出し欠落、必要シート欠落をテスト用コピーで確認する。共有台帳取得失敗として停止し、正常完了を表示しないこと。TC-4-1-1/17/23の「有効な台帳に候補がない」とは別。 |
| B07 | パス入力の別分岐 | C12/C15へ存在しないフォルダを指定する。正常系ではフォルダ指定と有効なフルファイルパス指定の両方を確認する。TC-2-1-4/5の「存在するフォルダに必要ファイルがない」と区別する。 |
| B08 | ファイル名・パスの境界 | 日本語・空白を含むSVNパス、PRの特別な会社別パス、BATCHの未知ディレクトリ/異なるサーバー名を、実運用に該当する範囲で確認する。追加された拡張子なしのBATCHファイルはフォルダ判定との境界も確認し、業務上の正しい扱いと照合する。 |
| B09 | 件数・文字数の境界 | 抽出ファイル数256件と257件で件数・最終行・連番を比較する。長い日本語メッセージ/ログ行では、256バイトを超える場合の省略と文字化け、案件照合への影響を確認する。 |
| B10 | エラー後の再実行 | A06/B05/B06などの失敗後、入力を正常に戻して実行する。Excelの画面更新・イベント・計算状態、進捗表示、不要な一時UPDATEタブの残留、正常再実行を確認する。各異常系の後処理としてまとめて確認できる。 |

## 新規ケースとは分けて管理する項目

- TC-3-1-3: 以前確認したSize/TimeStampの証跡間の不整合は、既存ケースの証跡修正事項。A08の明示的なリビジョン別確認に流用できるが、修正だけでA08の全条件を確認したことにはならない。
- TC-5-1-2: 「UPDATEシートあり・データなし」の分岐はすでに仕様書に存在する。前回レビューではその証跡が不足していたため、現時点で未追加なら証跡を補う。新規テストの追加漏れには数えない。
- TC-4-1-14/22/27の成功ケースの台帳証跡省略は、更新後の注記に従って扱う。
- AP/BATCHとPRの判定理由の表示列の差は、すでにユーザーが現状維持を了承した事項として今回の追加候補に数えていない。
- 意図的に対象外としたキャンセル操作・会社コード列欠落は、追加漏れとは扱っていない。
